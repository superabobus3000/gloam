# Gloam — правила работы агента

## Прочитать перед работой
1. `project/PROGRESS.md` — актуальная версия, принятые результаты, текущая задача и следующий шаг.
2. `project/SPEC.md` — требования пользователя и границы задачи.
3. `skills/minecraft-fabric/SKILL.md` и нужные тематические skills.
4. При проверках — `project/VALIDATION.md`. Исторические результаты не выдавать за свежие тесты.

## Текущее состояние
Minecraft Java **26.3**, Fabric, Java25. Текущая версия **0.4.2-alpha.1** (более мягкий свет/чаще светлячки ожидают оценки). Туман0.4.1 принят пользователем и не менялся. Предыдущая0.3.4 подтверждена пользователем. Единственный устанавливаемый артефакт — `deliverables/gloam.jar`.
Подтверждены портал, лесной ландшафт, фонари и исправление цепей. Деревни реализованы:5–7домов,2–3обычных жителя при генерации, без постоянного лимита/автовосстановления. Обычные деревни — только целиком новые5×5участки; starter — ограниченное исключение возле первого выхода. Добавлены чаще деревни/starter у первого выхода, owned light halos, постоянный серый fog и firefly particles. Следующий шаг — оценка пользователя; не начинать пещеры без новой задачи.

## Жёсткое ограничение ресурсов
- **Не запускать графический Minecraft-клиент, runClient, quick-play или визуальные игровые тесты.** Пользователь сообщил о сильных зависаниях; доступно около2ГБ RAM. Скриншоты/визуальную оценку получать от пользователя.
- Не устанавливать и не прогревать toolchain просто для уборки/документации. Не запускать gradle build без изменений, требующих сборки.
- Начинать с чтения кода, небольших unit-тестов и статических проверок. Не запускать genSources и тяжёлые watchers.
- При необходимой сборке: Java25, Gradle -Xmx384m, workers2, no parallel, ActiveProcessorCount2, --no-daemon (настройки уже в gradle.properties).
- Dedicated server допустим только для необходимой проверки логики, один за раз, с ограничением памяти (нынешний dev run -Xmx768m), малой дистанцией и временным миром. Не запускать параллельно отдельную сборку/второй сервер/клиент. После теста штатно остановить сервер, проверить выход процесса, удалить мир и временные файлы.
- Фоновые процессы платформы не останавливать. Завершать только собственные процессы проекта. Файловый размер workspace не равен использованию RAM.

## Не нарушать при изменениях
- Сохранять согласованный рельеф и геометрию портала; не менять их попутно.
- Между лесными фонарями ≥40XZ; текущая схема гарантирует41. Лесные фонари/цепи — вощёная состаренная медь. Не создавать дубли и не перемещать старые фонари при замене материала.
- Не возвращать одноразовую copperCells-миграцию: она могла навсегда пропускать оставшиеся железные цепи. Текущий независимый обработчик — LanternChains.
- Не требовать удаления мира/индекса ради обновления цепей. Не ослаблять общую защиту арок.
- Не объявлять клиентскую/LAN-проверку завершённой по результату компиляции или headless-теста.
- Если сообщение явно дублирует прежнее из-за сбоя интерфейса, не повторять уже завершённую работу. Пользователь отдельно предупредил об этом; новое конкретное сообщение об ошибке учитывать.

## Файлы и выдача
- Выдавать **только gloam.jar**, без номера версии в имени, ZIP и исходных архивов. Внутреннюю версию обновлять при изменении мода; не при уборке документации.
- Не удалять последний рабочий JAR до успешной проверки замены. После публикации не хранить старые релизы.
- Сохранять исходники, ресурсы, Gradle wrapper/конфигурацию, тесты, генераторы ресурсов, лицензии и рабочий CI. Это нужные файлы, а не мусор.
- Удалять build/run/cache, тестовые миры, дубли и сырые исследовательские дампы после переноса полезных результатов в документацию. Не создавать архивы мусора.
- **Скриншоты удалять сразу после анализа**, не копировать, не архивировать и не сохранять нигде.

## После каждой задачи
1. Обновить `project/PROGRESS.md`: что сделано, что реально проверено, что осталось.
2. Обновить соответствующие `skills/*/SKILL.md` проверенными знаниями; выделять новые темы при необходимости.
3. Обновить VALIDATION при проверке сборки; SPEC — при согласованном изменении требований.
4. Убрать временные данные/свои процессы. Не оставлять ссылки на удалённые отчёты как на существующие.
5. Не путать предложенный следующий этап с разрешением начать его.
