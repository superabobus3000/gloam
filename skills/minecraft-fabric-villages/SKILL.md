# Деревни — этап0.4.0

## Согласовано пользователем
5–7домов; наполовину заброшенный/частично разрушенный облик. При генерации2–3обычных жителя, **не постоянный предел**: дальше обычное размножение Minecraft, без восстановления погибших. Редкие небольшие поляны только вместе с поселением. Лесной рельеф/порталы/освещение за пределами поселения не менять. Пещеры и домики ведьм вне этого этапа. Замшелые пещеры в будущем редкие и просторные, не преобладающие.

## Реализация
- VillageLayout: один кандидат в1024×1024блока, origin chunk offset16..43 в регионе64×64чанка. Минимальное расстояние между центрами соседних кандидатов592блока, фактические поселения реже из-за preflight. floorDiv/floorMod для отрицательных координат.
- Поселение занимает5×5чанков (80×80), поляна — слегка асимметричная окружность радиуса39±0.3. Все7позиций домов с проверочным отступом5блоков внутри неё. Две жилые избы с целыми крышами/дверями, остальные3–5разрушены. Еловое дерево, тёмные крыши, мшистый камень, битые окна, паутина и обломки; общий колодец, маленькая грядка и разреженные медные огни.
- Это physical clearing среди собственных лесных биомов, **не добавленный plains-biome** и не ванильная jigsaw structure. Появление не доступно через ванильный locate structure; отдельные команды ниже. JSON измерения/биомов/terrain не менялись.
- Естественные мягкие неровности поляны сохраняются, локальные фундаменты/пороги подгоняются к поверхности. До вырубки проверяются вся сухая поляна, почва/высота/уклон, все участки домов, граница мира, арки, block entities и inhabitedTime. Болота/вода/опасные пересечения отклоняются; отклонённый кандидат не оставляет поляны. Пропускаются и естественные block entities, включая возможные ульи/сердца скрипуна: политика консервативная, частота не обещана точно.

## События и ограничения
- NaturalVillages получает CHUNK_LOAD(level,chunk,generated); fresh BitSet помечает ТОЛЬКОgenerated=true и только в текущей сессии. Требуются все25новых чанков и getChunkNow для каждого: нет принудительной загрузки/рекурсивной генерации соседей.
- FULL_CHUNK_STATUS_CHANGE повторно ставит уже известный fresh-кандидат в очередь при cached reaccess; не делает старый чанк новым. Один кандидат на5тиков, до100повторных ожиданий недоступных соседей, новая активация может возобновить ожидание.
- **Старые и частично старые участки не переделываются.** При перезапуске fresh-маска сбрасывается; кандидат, часть которого исследовали в прошлой сессии, пропускается. Для появления исследовать полностью новые участки измерения с достаточной дальностью прорисовки (вся область5×5 должна стать FULL). Новый мир не обязателен.
- Генерация одного поселения выполняется за один серверный job; не утверждать нулевые задержки на любом ПК. Нет постоянного сканирования мира/загрузки тысяч чанков. Возможна краткая нагрузка при генерации новой деревни. Отдельный staged-builder с восстановлением фаз ещё не сделан.

## Индекс и жители
`data/gloam-villages.json`, format1, villages + skipped. В villages origin x/z, houses, residents, spawned, stage и UUID жителей. Запись атомарным rename (с fallback), до строительства сохраняется intent, после строительства/спавна сохраняется done. Повреждённый индекс останавливает деревни и не перезаписывается. Не советовать удалять индекс.
Повторное размещение любого зарегистрированного site не выполняется. У жителей vanilla AI/trading, persistent flag и теги gloam_village/gloam_village_RX_RZ.3кровати,2бочки и компостер обеспечивают обычные POI; счётчик spawned — исторический, **не живое число оставшихся жителей**. Погибших не заменяет мод, размножение не перехватывается.
Проверена обычная save/stop/restart, **не аварийный crash между world save и JSON/entity write**. При interrupted/building/spawning индекс не запускает автоматическую реконструкцию/второе население; возможна частичная постройка, требующая диагностики. Не обещать crash-atomicity.

## Взаимодействие с прежними системами
- ForestLanterns.place исключает reserved meadow, hasExisting исключает её декоративные лампы из лесного индекса. Лесные лампы в углах80×80 вне окружности допустимы и сохраняют прежний минимум41XZ. Нельзя проверять расстояния между ВСЕМИ лампами деревни общим checker для леса.
- Естественные порталы и RealmPlacement для связанного выхода исключают reserved meadow. Preflight деревни также проверяет protected footprint зарегистрированных арок (пары+natural). Административный /gloam create намеренно заменяет terrain и не предназначен для живой деревни.
- LanternChains и защитные mixins не изменены; медь у нового колодца сразу нужного типа.

## API26.3 и MCA
- EntityTypes.VILLAGER, **не EntityType.VILLAGER**; Blocks.BED.brown(), **не Blocks.BROWN_BED**. Реальная ColorCollection имеет pick(DyeColor), не get.
- EntityTypes.VILLAGER.spawn(ServerLevel,BlockPos,EntitySpawnReason.STRUCTURE) делает обычный vanilla spawn/init. Затем persistence+теги. Нет client imports в общем коде.
- Для двух половин кроватей/дверей используется UPDATE_CLIENTS|UPDATE_KNOWN_SHAPE, чтобы не обновлять форму в промежуточном неполном состоянии. Не применять это как глобальное отключение защиты.
-26.3palette может не хранить default properties вообще: строка minecraft:brown_bed означает default foot/north/occupied=false. Head/nondefault обычно имеют явные properties. Пустые свойства не доказывают исчезнувшую половину кровати! В inspector нормализуются default bed/door properties. Первое ошибочное чтение дало ложное сообщение об отсутствующих feet; реальные RCON if block подтвердили целые пары.
- Inspector `gloam/tests/inspect_village_world.py` проверяет MCA-полы/крыши, обе половины и ориентацию3кроватей/2дверей, поддержку и1-блочные перепады4шагов порогов, колодец/ферму/лампы. Огни сверять по семи точным декоративным XZ, а не числу всех ламп во всём квадрате80×80: лесные могут оставаться в углах за круглой поляной.
