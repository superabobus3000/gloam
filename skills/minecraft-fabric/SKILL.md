Составлено 2026-10-06 по просмотренным официальным материалам. Это авторская рабочая инструкция, а не установленное расширение и не скачанный чужой skill. Перед работой читать этот файл. Не считать его заменой исходникам конкретной версии.

## 1. Фиксация окружения

- Цель пользователя: Minecraft Java 26.3, Fabric. Не заменять на 1.21 или snapshot.
- Проверить точный релиз, JDK, Loader, Fabric API, Loom, Gradle по официальному шаблону и метаданным. JDK 25 подтверждён метаданными игры, официальным шаблоном и успешной сборкой.
- Использовать wrapper; фиксировать зависимости без динамических latest/+.
- Не смешивать имена классов и методы из разных mappings/версий.
- Сначала собрать неизменённый минимальный шаблон, затем добавлять функции.

## 2. Спецификация до кода

Уточнить mod_id, источник портала (постройка игрока / генерация), размеры и ориентации, активацию и стоимость, отключение и разрушение, задержку перехода, возврат, несколько входов, мультиплеер, перенос сущностей.
Для измерения: рельеф, биомы, блоки, небо, освещение, время, погода, опасности, кровати, смерть/возрождение, структуры и масштаб координат.
Не добавлять сложные игровые правила без согласования.

## 3. Архитектура

- Разделять регистрацию контента, проверку конструкции, телепортацию, данные мира и клиентские эффекты.
- Игровые решения принимает сервер. Клиент отображает, но не утверждает стоимость, координаты и валидность входа.
- Client-only классы не должны загружаться на dedicated server.
- Предпочитать ванильные data-driven механизмы и Fabric events; mixin только при отсутствии достаточного API с пояснением причины.

## 4. Измерение

- Сначала минимальное измерение на существующей генерации, вход командой и площадка прибытия.
- Разделять dimension и dimension_type; схему JSON проверять по данным 26.3.
- Использовать noise settings / biome source / configured и placed features, если это решает задачу; custom ChunkGenerator лишь при необходимости.
- Не менять namespace после выпуска миров без миграции.
- Проверять ошибки registry/codec при загрузке нового мира и после перезапуска.

## 5. Портал

- Проверять форму только при нужных событиях, не сканировать весь мир каждый тик.
- Ограничить область проверки, корректно учитывать повороты, край мира и незагруженные чанки.
- Проверять существование измерения, безопасное прибытие, коллизии, высоту, опору и жидкости.
- Добавить cooldown и защиту от циклического перехода и двойного списания предметов.
- Явно определить возврат и поведение при разрушенном выходе.
- Если сохраняется точка возврата: UUID игрока, ключ измерения, координаты и ориентация; persistence и обработка недействительного адреса.
- Не обещать API телепортации до проверки исходников 26.3.

## 6. Структура

- Мультиблок игрока и worldgen structure — разные задачи.
- Сначала ручная установка, затем шаблон NBT и размещение.
- Jigsaw для модульности; не вводить без необходимости.
- Проверить schema structure / structure_set / template_pool и biome tags целевой версии.
- Проверить повороты, высоту, стыковку с рельефом, частоту, биомы. Генерацию проверять в новых чанках.

## 7. Ресурсы и качество

- Предпочитать datagen для повторяющихся JSON, если доступно в целевой версии.
- Подготовить blockstates, модели, текстуры, переводы ru_ru/en_us, loot tables, tags, рецепты по согласованному контенту.
- Не использовать чужие ассеты/код без проверки лицензии.
- Сохранять исходники и инструкции. Не включать клиент игры, учётные данные и чужие миры в архив.

## 8. Контрольные этапы

1. Минимальный шаблон собирается.
2. Измерение загружается.
3. Работает вход и выход через тестовый блок.
4. Работает проверка конструкции и активация.
5. Работает естественная генерация входа, если нужна.
6. Добавлены уникальный ландшафт и визуальные ресурсы.
7. Проверены сохранение/перезапуск, dedicated server и два игрока.

Тест-кейсы: неверная форма, повторная активация, полный/пустой инвентарь, сломанный выход, несколько порталов, одновременный вход игроков, смерть, выход из игры, рестарт, непригодная точка прибытия.

## 9. Честность отчётности

Указывать отдельно: написано / скомпилировано / сервер запущен / проверено в клиенте. Успешная сборка не равна игровому тесту. Если среда не позволяет запуск Minecraft или загрузку зависимостей, сообщить ограничение и дать пользователю точные шаги проверки и сбор логов. Не выдавать гипотетический JAR за протестированный.

- Обновлять этот SKILL.md проверенными знаниями, найденными ограничениями и текущим статусом; не записывать предположения как факты.
- Скриншоты удалять сразу после анализа, без копирования или архивирования.

- После успешной новой сборки заменять предыдущий deliverables/gloam.jar, удалять старые релизы, дубли и ненужные временные файлы. До успешной сборки не удалять единственный рабочий результат.
- Сохранять актуальные исходники, необходимый NBT, ресурсы, ТЗ и результаты последней проверки.
- Удаление файлов из workspace не гарантирует удаления исторических карточек/ссылок в интерфейсе чата. Не утверждать, что интерфейс очищен, если доступна только файловая система.

## Проверенные знания по этому проекту

- Рабочая связка: Java 25, Minecraft 26.3, Loader 0.19.5, Fabric API 0.161.0+26.3, Loom 1.18.2, Gradle 9.7.1.
- Шаблон портала имеет размер 13×11×5. Проём между оградами: локальный X=10, Z=2, Y=2..4; задняя декоративная стена X=11. Не заменять её поверхностью портала.
- Новое размещение: origin Y на 7 блоков ниже ног игрока; в новом noise-мире высота выхода вычисляется от поверхности, а не фиксируется в Y=58. Позиция поверхности и проверка входа должны изменяться согласованно.
- Уже поставленные шаблоны не перестраиваются при замене JAR. Изменения размещения проверять на новой паре; автоматическую миграцию без согласования не выполнять.
- Связи хранятся в data/gloam-portals.json мира. Существующие пары alpha.1 поддержаны проверкой фактического блока портала на старой и новой плоскостях.
- Полная декомпиляция genSources в этой среде завершалась SIGKILL/137. Для точечных API использованы javap и ресурсы JAR целевой версии.
